🔄 FLUJO DE AUTENTICACIÓN Y AUTORIZACIÓN
═══════════════════════════════════════════════════════════════════════════════

CLIENTE
   │
   ├─ Envia credenciales (correo + contraseña)
   │
   ├─ AuthService genera JWT con:
   │  ├─ sub: userId
   │  ├─ correo: email
   │  └─ role: role (LEGACY)
   │
   └─ Bearer Token guardado en cliente
   
ACCESO A RUTA PROTEGIDA
   │
   ├─ @UseGuards(AuthGuard)
   │  └─ ✓ Verifica JWT válido
   │     └─ Extrae user del token
   │
   ├─ @UseGuards(RolesGuard) - Opcional
   │  └─ ✓ Verifica @Roles(Role.ADMIN)
   │     └─ Compara user.role
   │
   ├─ @UseGuards(PermissionsGuard) - Opcional
   │  └─ ✓ Verifica @RequirePermissions('orders.create')
   │     ├─ Obtiene roles del usuario (UserRole)
   │     ├─ Obtiene permisos del rol (RolePermission)
   │     └─ Valida si tiene permiso requerido
   │
   └─ ✓ Acceso permitido → Ejecuta handler
      ✗ Acceso denegado → 403 Forbidden

🎯 FLUJO DE SETUP INICIAL
═══════════════════════════════════════════════════════════════════════════════

1️⃣ EJECUTAR SEEDER
   $ npm run seed:run
   
   Crea automáticamente:
   ✓ 5 roles predefinidos (Admin, Técnico, Recepcionista, Cliente, User)
   ✓ 20+ permisos granulares (orders.*, users.*, roles.*, etc)
   ✓ Relaciones rol-permiso

2️⃣ CREAR USUARIO (vía Auth)
   POST /api/v1/auth/register
   {
     "cedula": "1234567890",
     "nombre": "Juan",
     "correo": "juan@tech.com",
     "password": "Seguro123!",
     "telefono": "0987654321",
     "ciudad": "Quito",
     "role": "Cliente"
   }

3️⃣ ASIGNAR ROL AL USUARIO
   POST /api/v1/user-roles/1/assign/2
   (Usuario 1, Rol 2 = Técnico)

4️⃣ USUARIO LOGEA
   POST /api/v1/auth/login
   {
     "correo": "juan@tech.com",
     "password": "Seguro123!"
   }
   
   Response:
   {
     "token": "eyJhbGc..."
   }

5️⃣ USAR TOKEN EN SOLICITUDES
   GET /api/v1/orders
   Headers:
   Authorization: Bearer eyJhbGc...
   
   Guard verifica:
   ✓ JWT válido
   ✓ Usuario tiene rol Técnico
   ✓ Rol Técnico tiene permiso 'orders.view'
   ✓ Acceso concedido

🛡️  GUARDS Y DECORATORS DISPONIBLES
═══════════════════════════════════════════════════════════════════════════════

GUARDS (Validadores):
─────────────────────
✓ AuthGuard             → Verifica JWT válido
✓ RolesGuard           → Verifica rol del usuario
✓ PermissionsGuard     → Verifica permisos específicos

DECORATORS (Configuradores):
──────────────────────────
✓ @Roles(Role.ADMIN)   → Restringe por rol
✓ @RequirePermissions  → Restringe por permiso
✓ @GetUser()           → Inyecta usuario actual

COMBINACIONES:
─────────────
// Solo lectura (rol)
@UseGuards(AuthGuard, RolesGuard)
@Roles(Role.ADMIN)

// Lectura + escritura (permiso)
@UseGuards(AuthGuard, PermissionsGuard)
@RequirePermissions('orders.create')

// Máxima seguridad (rol + permiso)
@UseGuards(AuthGuard, RolesGuard, PermissionsGuard)
@Roles(Role.ADMIN, Role.TECH)
@RequirePermissions('orders.update')

❓ PREGUNTAS FRECUENTES
═══════════════════════════════════════════════════════════════════════════════

P: ¿Cómo actualizar el JWT con nuevos roles?
R: El usuario debe volver a logear. El JWT se genera con roles actuales.

P: ¿Puedo tener múltiples roles en un usuario?
R: ✓ Sí, a través de UserRole. Verifica permisos de todos los roles.

P: ¿Diferencia entre Role.ENUM y roles flexibles?
R: Role.ENUM es legacy. El sistema nuevo usa roles BD con permisos granulares.

P: ¿Cómo crear un permiso dinámico?
R: POST /api/v1/permissions con nombre y slug únicos.

P: ¿Rendimiento con muchos permisos?
R: Usa eager loading (rolePermissions con @Relation).
